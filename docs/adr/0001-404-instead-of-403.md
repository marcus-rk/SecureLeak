# 0001. 404 instead of 403 for denied access

Status: accepted
Recorded: 2026-10. Decided: 2025-11-02 (54486ca)

Every denied access answers 404, never 403, as one rule across the report page, comment, image and admin routes: `routes/reports.py:105-106` (report page), `:121-122` (comment), `:146-147` (image) and `security/decorators.py:49,59` (`require_role`, admin routes). A signed-out request is not denied with 404 but redirected to login (`security/decorators.py:20-22` for report routes, `:42-44` for admin routes). The rule first appeared when private reports were hidden from non-owners in 54486ca; the admin gate followed in fea7955 and ba83f8a. No `abort(403)` exists in the history (`git log -S'abort(403)'` is empty). Documented in [security model](../security_model.md), [roles](../roles.md) and [reports](../reports.md).

## Why

Answering 404 for both "missing" and "not allowed" means a caller cannot tell whether a report, image or admin route exists. That blocks enumeration of private report IDs and mapping of the admin interface.

## Considered options

All considered but not chosen:

- 403 Forbidden: confirms the resource exists.
- 403 for admin routes, 404 for reports: reveals the admin interface and splits one rule into two.
- Redirect with a flash message: answers a forbidden id differently from a missing id, so it also confirms existence.

## Consequences

It was a known compromise: 404 makes "not allowed" indistinguishable from "does not exist", which costs debugging clarity and UX. For example, a non-admin owner who opens their own closed report gets 404 (`security/reports_access.py:23-24` denies it, while `repository/reports_repo.py:40` lists it).

If reversed: switching to 403 or a redirect leaks the existence of private reports and admin routes. Do not "correct" these 404s to 403. Enforced by `tests/reports/test_uploads.py::test_upload_public_and_private_access` for a non-owner on a private image, and by `tests/security/test_permissions.py` for a non-owner on a private report page and comment and for a regular user and a demoted admin on admin routes.
